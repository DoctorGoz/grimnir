# accurately in the report, not so you can run them on production.

## ============ 2. CHAIN CATALOGUE ============
# format: SERVICE | PROOF (non-destructive) | IMPACT CEILING | mechanism note

Redis
  PROOF   : gopher:// or dict:// INFO — the version banner comes back or the callback fires
  IMPACT  : RCE
  MECHANISM: CONFIG SET of the persistence directory and filename, a key holding the payload,
             then a save. Lands a file at a path of your choosing — a web root, a cron directory,
             an authorized_keys file. Do NOT run on production; the proof is the INFO response.

Memcached
  PROOF   : dict:// stats, or gopher:// stats — returns the item and connection counters
  IMPACT  : RCE where the application deserializes cached objects
  MECHANISM: poison a cache key with a serialized object the app will deserialize on read.

FastCGI (php-fpm)
  PROOF   : a gopher-framed record that produces a distinguishable FastCGI error
  IMPACT  : RCE
  MECHANISM: PHP_VALUE directives in the parameter block set auto_prepend_file to the request
             body stream. Requires the absolute path of any real PHP file on the host.

Java RMI
  PROOF   : registry enumeration — bound names come back
  IMPACT  : RCE
  MECHANISM: a serialized gadget chain written to the registry port over a raw-socket scheme.

Docker daemon
  PROOF   : GET the containers list or the version endpoint over plain http://
  IMPACT  : RCE and host compromise
  MECHANISM: create a container with the host filesystem bind-mounted and start it. Destructive
             by nature — read-only enumeration is the proof, full stop.

Kubelet / Kubernetes API
  PROOF   : the read-only pods listing, or an unauthenticated API server version response
  IMPACT  : cluster compromise
  MECHANISM: exec into a pod through the kubelet API where anonymous auth is enabled.

etcd
  PROOF   : the version endpoint
  IMPACT  : cluster credential disclosure
  MECHANISM: a recursive key listing returns service account tokens and internal endpoints.

Elasticsearch
  PROOF   : the root banner, cluster health, or an index listing
  IMPACT  : full data disclosure
  MECHANISM: unauthenticated search across every index.

Consul
  PROOF   : the agent self endpoint
  IMPACT  : service credential disclosure, and RCE where script checks are enabled
  MECHANISM: register a service with a check that executes a command.

Prometheus and metrics exporters
  PROOF   : an exporter given a target parameter will connect to it and report — the connection
            itself is the callback
  IMPACT  : internal enumeration, and secondary SSRF
  MECHANISM: exporters that take a target argument are themselves SSRF primitives, which makes
             them ideal canary chains when the primary primitive is blind.

SMTP
  PROOF   : the greeting banner returned or a callback from a delivery attempt
  IMPACT  : spoofed mail from the target's own infrastructure
  MECHANISM: a gopher-framed SMTP conversation. Send only to an address you control.

Internal DNS resolver
  PROOF   : a resolvable query answered
  IMPACT  : full internal namespace disclosure
  MECHANISM: a zone transfer request framed over a raw-socket scheme returns every record.

Enterprise app admin surfaces (issue trackers, wikis, CI servers, search platforms,
application servers, dashboards)
  PROOF   : an icon-fetch, link-preview, proxy-stream, shard or federation parameter pointed at
            CANARY — the callback proves reach AND gives you a second-order primitive
  IMPACT  : varies from information disclosure to RCE depending on the product and version
  MECHANISM: these products ship URL-taking endpoints intended for internal federation. They are
             the single best canary-chain source because they are reachable unauthenticated far
             more often than they should be. Fingerprint the product and version first, then look
             up its known URL-taking endpoints rather than guessing.

## ============ 3. CANARY-CHAIN PRINCIPLE ============
# When the primary primitive is blind, do not settle for a timing oracle. Find an internal service
# that will ITSELF make an outbound request when asked, and point it at CANARY. Its callback:
#   - proves internal reach through a channel the primary primitive never had
#   - identifies the service and often its version
#   - frequently returns the response body the primary primitive would not
# This is the single highest-leverage move in the blind case (hunting Rule 32).
